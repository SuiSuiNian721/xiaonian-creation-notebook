# 人设与连续陪伴

「人设与记忆」现在提供精简版和完整版。精简版保留基础人设与记忆；完整版加入数值状态、情境规则、表达学习和高级运行能力。切换方法、记忆与纠错原理、数值如何影响回复，以及请求／token 用量见 [两种版本的用户说明](workbench-character-modes.md)。下方能力矩阵描述完整版能力。

角色资料、QQ 和虚拟陪伴现在都提供「人设与记忆」入口。QQ 使用自己绑定的角色，顶栏切换角色不会把 QQ 换绑。修改共用人设会增加版本；QQ 重新绑定后使用新版本，旧对话保留原快照。

## 使用

1. 在角色资料创建或导入 JSON / PNG 角色卡，再打开「人设与记忆」。PNG 上限 8 MiB，JSON 上限 2 MiB，原始未知字段保留。
2. 在「人设」「世界书」整理角色内容。提示词预览显示实际注入的资料和触发轨迹；对话预演会使用所选模块的 AI，不向 QQ 发消息，也不提交状态变化。
3. 「记忆」自动分为会话摘要、对话对象特点、共同经历与关系、计划与待办，并保留来源原话；可纠正、删除、归档、置顶和设置到期时间。同一角色实例中同一联系人的明确现实记忆默认跨普通会话延续，剧情与初步理解留在原会话；不同联系人和群聊身份分别保存。旧手工记忆仍按原有共享范围使用。向量召回需要自行填写 embedding 服务，未配置时仍有关键词与实体关系召回。
4. 「状态」管理共同心情、精力，以及当前会话的关系、活动、剧情和变量。对话中生成的变量在确认回复送达后才提交，生成期间手动编辑的版本优先。
5. 「互动」控制主动联系、安静时间、次数、群聊观察、动态、求助和余额提醒。主动联系和外部发布默认关闭；QQ 的暂停、名单和连接状态仍优先。
6. 「工具」添加自己的 HTTP 服务，或选择「工作台绘图」复用已导入的 ComfyUI 工作流与提示词字段。工具默认未启用，不自带服务密钥或替换模型。图片/声音服务需返回可读取的 URL。
7. 「脚本」显示兼容范围。启用后可运行受限脚本、预演变量和查看状态栏；预演变量需要明确点击应用才保存。

每轮自动记忆、摘要和完整版状态共用原有的观察请求；已有可靠聊天另由后台分批补整理，不要求逐条确认。查看记忆页不调用模型。向量召回、群聊加入判断、主动消息、动态和工具会各自使用配置好的服务；未配置的媒体功能会留下错误记录，不伪装执行成功。

## 脚本与变量的执行顺序

完整版且开启角色脚本后，初始变量、生成前脚本和模板计算的结果会进入本轮实际提示词。脚本修改、添加或删除的消息作用于本轮消息副本；修改图片消息的文字会保留图片，工具调用与工具结果字段也会保留，不会直接重写 QQ 已保存的聊天历史。

首次载入变量时派发 `VARIABLE_INITIALIZED(variables, swipe_id)`。输出处理按下面的顺序执行：

1. `VARIABLE_UPDATE_STARTED(variables)`：回调可修改应用命令前的变量。
2. `COMMAND_PARSED(variables, commands, message_content)`：回调可修正或增删已经解析的数据命令。
3. 应用命令；同一变量块内任意操作失败，该块不提交部分结果。
4. `VARIABLE_UPDATE_ENDED(variables, variables_before_update)`：可对照更新前的快照限制变化。
5. `BEFORE_MESSAGE_UPDATE({variables, message_content})`：可修改最终变量和显示正文。
6. `MESSAGE_RECEIVED(message_id)`：消息编号使用脚本增删后的当前副本，改写当前回复会进入显示正文。

每次生成前渲染或输出处理都会建立独立的受限执行环境，先按顺序加载本次启用的脚本，再派发该次处理的各个事件；同次处理不会为每个事件重新运行脚本主体。它仍然不是跨轮常驻的酒馆后台环境。

原生命令的 `commands` 使用 Tavern Helper 的 `type/args/full_match/reason` 数据结构，除路径外的参数是字面量字符串。JSONPatch 命令也提供 `args`，其中路径保留 JSON Pointer 形式和转义，同时保留 `op/path/value/from` 字段；只修改后者也能生效，同时修改两组字段时以 `args` 为准。模型命令只解析数据，不作为 JavaScript 执行。初始化事件兼容 `mag_variable_initiailized` 的历史拼写与 `mag_variable_initialized` 的标准拼写。

脚本加载或监听失败会回滚该段变量、消息、动作和监听改动，记录脚本名称及事件；其他已成功的脚本与合法模型补丁保留。异步初始化会等同批回调结束后再提交或回滚，嵌套事件不会等待自身。无限循环或无法完成的异步任务仍受沙盒超时限制。

脚本开关和变量更新规则沿用当前角色的设置。程序更新不会自动开启脚本，也不会替角色新增规则；修改卡内脚本后，QQ 仍需重新绑定新版本快照才能使用。

## 兼容边界

- 本轮是工作台自己的共用实现。没有打包八个上游的完整应用、原有人设、表情包、默认模型或私有配置。来源与固定版本见 [来源清单](character-life-sources.md)。外部 API 服务需要自己的地址和权限；未把某个第三方的 122 个在线接口当作工作台自带免费服务。
- 不保证任意酒馆脚本直接运行。宿主 DOM、网络、CDN、完整 lodash/jQuery/zod/Vue、STScript、长期后台脚本生命周期，以及部分世界书高级规则尚不支持；逐项列表在运行层能力说明中。EJS 使用当前会话作用域，不冒称完整酒馆全局环境。
- 原生陪伴的模型流目前需要完整接收、处理变量后再展示，首字等待时间会增加。外部 URL 音频不保证口型同步；表情和动作是否存在取决于用户导入的模型。
- 内置绘图复用现有连接，不自动启动 ComfyUI。取消等待不会擅自取消共享队列任务，可在「角色绘图」中查看、继续管理。QQ 的本机图片 URL 适用于与工作台同机的 NapCat；远端 OneBot 需要能访问图片的服务地址。归档图片在绘图模块持久保存，本机临时服务地址随工作台会话变化。
- 当前分支继承模块使用说明、首次引导和桌面沉浸模式；本轮不包含手机布局、真实 QQ 外发验收或完整桌面重新打包。

## 验证记录

新增回归覆盖上表机制。完整测试日志在当前工作区 `qa/character-life/`，桌面编辑器截图在 `.impeccable/review/character-life/` 与 `qa-output/character-life-media/`。这些 fixture、源码与桌面检查不能替代用户的实际模型、QQ 账户、第三方工具和工作流运行。

本轮完整测试共 504 项，500 通过、4 项真实 Python 环境用例跳过、0 失败；末轮修改后，角色运行层、连续陪伴、QQ 和虚拟陪伴定向回归 140 项全部通过。原生 Electron QA 17 项通过，结果位于 `qa/character-life-native/result.json`，包括实际助手回复落库后再写入有来源的长期记忆。
