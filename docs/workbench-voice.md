# 声音生成与声音克隆

「声音生成」根据文字描述从零创建声音，不要求录音；「声音克隆」根据参考录音创建音色。两个模块共用模型环境与音色库，未保存的试听分别属于各自实例。保存的是声音参考和生成信息，不重新训练权重。保存后的音色由克隆模型继续合成其他台词。

1. 添加「声音生成」或「声音克隆」，展开「声音组件」，点击「检测已有环境」，或在 App 内下载安装所需组件。生成与克隆模型共用一份音频编解码器。安装成功后自动填写配置，高级配置仍可手动选择本地路径。
2. 生成模块输入声音描述与短试听台词；克隆模块选择单人录音并填写试听台词。录音支持 WAV、FLAC、MP3、OGG，1–30 秒、最大 32 MiB，源文件保持不变。完整 WAV 就绪后手动播放。
3. 喜欢时输入名称，保存到音色库。保存参考需为 1–30 秒；过长的设计试听需缩短台词后重新生成。音色库可以用同一声音朗读其他台词，每次最多 500 字符。
4. 导入角色后，点击「用于当前角色」，或在人设窗口选择已保存音色。「语音发送」默认选「仅在明确要求时」，也可选「每条回复」。保存音色不会自动绑定角色，陪伴与 QQ 各实例保留独立角色设置。
5. QQ 仍需扫码登录、绑定角色、配置允许名单并连接。预演不会调用真实合成或发送。

组件安装当前支持 Windows x64，实际 MOSS 推理需要兼容 CUDA 的 NVIDIA 显卡。安装使用固定官方版本与文件 SHA-256；显示下载与校验阶段，取消保留已下载部分以供续传。运行环境单独安装在资料目录内，不修改系统 Python 注册或命令入口。首次安装需联网，下载完成后模型离线加载。

现有「温暖清亮」声音仅用于测试，不代表小璃，也不代表其他角色。旧内部标识 `xiaoli-warm-bright` 为兼容已有绑定保留；界面统一显示「测试音色 · 温暖清亮」。其独立服务配置收在「测试音色服务配置」中：

本机默认配置：

- Python：`E:\voice\envs\moss-py312\Scripts\python.exe`
- 配方：`E:\voice\data\outputs\MOSS_小璃固定参考克隆_20261108\固定参考配置.json`
- 服务：`http://127.0.0.1:17866`

服务仅监听回环地址，按固定参考 SHA-256 校验身份，串行执行推理；模型和解码器分阶段使用显卡，完成后释放显存。缓存按配方哈希、音色与台词归属。音频通过带签名的宿主地址提供，不能按任意本机路径读取。

新生成与克隆使用工作台自己的工作进程；取消会终止本次受管进程并丢弃候选。旧测试音色服务的「取消等待」会丢弃该请求结果，正在执行的 Torch 推理继续完成并清理资源。各声音入口共用推理队列。切换角色、会话、用户轮次或修改声音设置后，旧声音不得交付。

「仅在明确要求时」只检查当前用户消息，例如「回复一条语音」「语音回复我」「读给我听」。普通聊天、询问能否发语音、引用/代码，以及「不要发语音」「只发文字」不会触发；上一轮的语音要求不带到下一轮。模型自行附加 voice 动作也不能绕过此规则。手动点击「生成声音」不受自动发送方式限制。旧的已开启声音记录在尚未选择新模式前保留原来的每条回复行为。

模型上下文会说明：文字由模型生成，实际合成和发送由工作台处理。它可以说明支持语音，但不能在实际完成前声称已经送达。

当前 QQ 网关、机器人编排、聊天资料和 MOSS 服务都在本机。电脑需要开机、联网并保持工作台运行；最小化可以继续运行，退出工作台、睡眠或关机则停止。接入文字模型 API 只会把文字推理交给远端，不会替代常驻机器人程序。若要电脑关闭后继续在线，需要把 QQ 网关和工作台后端部署到常开设备；语音若仍依赖本机 MOSS，关机期间仍不可用，需要另外部署语音服务或使用语音 API。

旧测试音色的手动真实合成验收（使用隔离资料，会调用显卡）：

```powershell
node tools/qa-shared-voice.mjs
```

服务单独验证方式见 `integrations/moss-voice/README.md`。Node 回归使用本地协议替身；模拟 OneBot 的确认只证明适配链路，不能代替真实 QQ 客户端收听。

`tools/qa-voice-studio.mjs` 在 Electron 中检查两个模块的完整操作；设置 `AI_FUTURE_VOICE_REAL=1` 时会检测并复用本机模型，实际执行声音设计、已保存音色合成和录音克隆。默认使用协议替身，不在普通测试中占用显卡。两种检查都使用独立资料、静音播放，不发送 QQ 消息。
