# 精简版与完整版

在「添加模块」中按需选择下面四个入口。添加入口后还需查看清单并确认安装；没有自动安装，添加也不会调用模型。

| 模块 | 用途 | 共用组件 |
| --- | --- | --- |
| 角色系统·精简版 | 为 QQ、陪伴提供基本人设与记忆 | 基础角色组件 |
| 角色系统·完整版 | 增加变量、状态、规则与表达习惯 | 基础角色组件 + 完整角色组件 |
| 虚拟陪伴·精简版 | 独立的文字聊天与沉浸模式 | 基础角色组件 + 精简陪伴组件 |
| 虚拟陪伴·完整版 | 原生角色舞台、聊天、语音设置与桌面陪伴 | 完整角色组件及其依赖 + 完整陪伴组件 |

当前组件包随工作台分发，通过本机安装器安装与校验；可保存安装包，也可在安装页选择已保存的本地包，再查看清单并确认安装。导入时验证模块、版本和文件内容，经过修改的包不能直接运行。尚未接入远程发布下载服务。公共引擎由工作台提供，可选包提供实际运行时使用的提示词和行为策略，不包含大模型权重。完整版的原生舞台运行环境、Live2D／VRM 和语音服务仍需另行准备，不能把这个小型组件包视为这些资源的完整下载。

已安装且校验通过的公共组件会复用。进入已安装的角色系统，选择角色并点击「为此角色使用…」；也可以在角色资料、虚拟陪伴或 QQ 的「人设与记忆」顶部切换已安装版本。同一角色共用人设、记忆和配置，切换不会清空高级资料。精简陪伴始终使用精简能力，不改变角色在其他模块中的版本选择。

新角色默认精简版，已经保存过旧版互动配置的角色按完整版保留偏好。缺失或损坏的组件不能运行对应能力，资料仍保留。移除入口也会保留组件文件与角色资料。

| 功能 | 精简版 | 完整版 |
| --- | --- | --- |
| 基本人设、性格、情境、开场与对话示例 | 使用 | 使用 |
| 长期记忆、来源查看、纠正、删除、归档、置顶 | 支持 | 支持 |
| 自动记忆整理 | 可关闭 | 可关闭 |
| 心情值、精力、关系值、活动与剧情 | 保留资料，运行时不使用 | 参与回复与状态整理 |
| 表达习惯 | 保留资料，运行时不使用 | 可学习、编辑、停用 |
| 世界书、变量、脚本、状态栏 | 保留资料，运行时不使用 | 按配置启用 |
| 群聊参与判断、主动联系、工具与媒体 | 不运行 | 按配置启用 |

## 记忆怎样工作

1. QQ 与原生陪伴确认回复送达后，系统把这一轮对话交给所选模型整理；精简陪伴以回复成功保存到会话为准，重开后仍可查看。摘要、对象特点、共同经历与关系、计划会自动提炼并写入，不要求逐条确认。重点必须带有用户消息中的来源原话；没有明确事实时可以不新增重点，推测显示为「初步理解」。
2. 记忆保存在当前角色实例的本机数据库。默认延续同一联系人明确的现实偏好与现实经历；不同联系人、私聊与群聊身份分别保存。每段会话有自己的摘要，剧情和不确定理解留在原会话；计划保留时间、完成和过期状态，完成或过期后不再作为待办召回。「同一对象的现实记忆跨会话延续」控制新分层记录；旧手工记忆继续使用原共享范围。
3. 下次对话按关键词、相关实体关系、时间和置顶情况找出相关条目。配置向量服务后还能按语义查找。召回的条目会随本轮请求发给所选模型，并非每次把整个记忆库发出去。
4. 用户可以看来源原话、纠正错误、归档、删除或设置到期时间。改正后旧条目不再参与召回；系统记录被替换或删除的内容，阻止完全相同的错误候选再次写入。AI 仍可能用不同说法产生误记，因此来源与纠正入口一直保留。

记忆条目与聊天记录分别保存，删除记忆不会删除原聊天。衰减降低旧记忆的召回优先级，不等于自动抹掉聊天。置顶用于保留重要约定，不代表内容已经由系统核实为真。

已保存的可靠旧聊天会在活动模块连接或使用时自动分批补整理，重新开启自动整理也会继续处理；进度落盘，重启可续接，失败不推进成功水位。范围包括本机 QQ 已确认回复、精简陪伴已保存聊天和升级后原生陪伴确认的来源，不包括其他应用的旧 AIRI 历史。记忆页只读取和管理结果，关闭页面不影响后台整理；复制或导出角色不会携带这些私人记忆与来源。

## 完整版怎样作出选择

心情值、精力、关系值是 0–100 的角色行为参数，用户可以手动修改。心情和精力由同一角色共用，关系值随会话保存；自动整理每轮最多调整 10 点，人工修改优先。

「状态」中可以设置条件规则。每条规则包含环境、数值、比较条件、阈值和回应方式，按显示顺序采用第一条匹配规则。例如：

- 精力 ≤ 30：回复简短，减少展开。
- 群聊中心情值 ≤ 35：未被提及时先旁观。
- 关系值 ≥ 70：表达更熟悉、自然。

直接对话或明确提及时仍会回应。旁观规则主要控制未被提及的群聊和主动联系；QQ 的暂停、允许名单和人工接管仍然生效。规则选择的回应方式会写入模型的本轮上下文；自然语言的具体表达仍由模型生成。

环境使用当前消息的私聊／群聊来源，主动联系单独标记；不会读取麦克风、桌面或现实环境来猜测用户处境。可以自行增加、编辑和移除规则。没有匹配时采用正常回应。

回复送达后，模型在同一次综合整理中更新记忆、状态、表达与回顾。取消、未确认送达、人工编辑后的旧结果，以及切换模式前的迟到结果不会覆盖当前状态。表达习惯保存为独立条目，只作为说话参考，可以停用或纠正。

## 请求与 token 用量

以下是普通一轮文字聊天的典型流程，不是固定账单：

| 选择 | 典型模型请求 | 主要 token 内容 |
| --- | --- | --- |
| 精简版，自动记忆关闭 | 1 次回复 | 人设、近期历史、召回记忆和回复 |
| 精简版，自动记忆开启 | 1 次回复 + 1 次记忆整理 | 上述内容，加上该轮对话与提取结果 |
| 完整版 | 1 次回复 + 1 次综合整理 | 人设、历史、记忆、状态、规则，以及记忆／状态／表达整理结果 |

完整版通常会消耗更多 token：输入中有状态、规则和可能触发的世界书，后台输出也更长。整理请求即使不显示在聊天窗口中，也会计入模型用量。关闭完整版的自动记忆后，综合状态整理仍会运行；想只保留基础对话可切换精简版。

本地数值比较、记忆排序、手动纠错、查看记忆页与提示词不调用对话模型。摘要与分类复用表中的每轮整理请求；旧历史补整理按批次增加请求，QQ 原有长上下文摘要、群聊加入判断、主动消息、工具续答也可能增加请求；向量服务、语音和图片服务按各自服务计费。「预演回复」会调用已配置模型，也会产生用量，但不保存预演状态、不发送 QQ 消息。

实际费用取决于所选模型的输入／输出计价、历史与人设长度、缓存和外部服务。本界面说明调用方式，不把字符数当成真实 token，也不承诺固定倍数或金额。需要降低用量时，先选择精简版、关闭自动整理或减少召回条数，再考虑缩短人设与对话历史。
