# 绘图与 ComfyUI 启动器 0.7.1

0.7.1 每项设置固定显示一句效果说明。标签优先说明用途，选项说明速度、显存与兼容性的取舍，技术名称和限制放在 info；实际参数语义与 0.7.0 相同。

左侧两个入口分别承担创作与环境管理：

| 入口 | 页面与用途 |
| --- | --- |
| 角色绘图 | 绘图、工作流与 MCP、连接配置、运行记录；导入和修改工作流、AI 候选预检与采用、MCP 接入、参数编辑、生成与作品 |
| ComfyUI 启动器 | 启动、模型与插件、快照、环境配置、记录；本体检测、启动参数、诊断、日志与维护 |

两边共用原 `drawing` 环境配置，没有第二份服务地址、Python 或模型目录。关闭角色绘图后仍可启动和维护；关闭启动器后仍可从角色绘图连接远端出图。首次升级仅在原先已启用绘图时同时启用启动器，之后用户停用会保持。旧配置、角色、工作流和作品保留。

## 启动与参数

先在「环境配置」保存本体、服务地址及作品目录，再到「启动」指定 Python（留空自动选择）并保存。服务启动只接受本机回环 HTTP 地址；角色绘图仍可配置远端服务。

服务地址留空时使用 `http://127.0.0.1:8188`，配置表单显示实际默认值；只采用检测出的本体路径并保存，也会保存这个地址。旧资料缺少地址时，启动预览、连接和环境管理使用同一默认值，下次保存配置时落盘。已有自定义地址和端口始终保留，远端地址仍只能连接，不能由本机启动。

「保存设置」不启动；「恢复默认」只回填草稿，保存后生效。存在未保存修改时，启动按钮禁用。更换本体或 Python 后，旧值继续显示；不可用的布尔、数字字段可用「还原此项」单独回默认，不改变其他参数。下拉选项可回自动/关闭。切换页面保留草稿，日志轮询与诊断返回不覆盖继续编辑的值。

「停止」支持当前工作台持有的进程，以及已连接、经 Windows 核实身份的本机外部服务。点击后显示目标 PID 与 Python 路径，确认才结束进程；取消不结束。外部服务先验证当前连接是 ComfyUI，再核对唯一监听 PID、指定解释器、main.py 入口及端口、进程创建时间和完整命令摘要，确认时重新核实并持有同一内核句柄。相对 main.py 不代表已核实工作目录。远程服务、身份不完整、目标变化或过期确认均拒绝。停止会中断当前生成，未完成结果可能无法保存；不会结束其他 Python、父进程或进程树。

本体移除的实验优化仍显示为旧勾选，允许单独取消，取消后不能重新选入。不支持的选项原因集中在字段 info，可通过焦点或点击读取。

表单由后端 30 个字段的模式生成：

| 分组 | 提供的设置 |
| --- | --- |
| 启动程序 | 自动选择或指定启动用的 Python |
| 计算设备与省显存 | 用什么出图、使用哪张显卡、省显存程度、给其他程序预留显存、按需占用显存、保留模型 |
| 计算加速与黑图排查 | 选择省显存的计算方案；提高精度尝试修复黑图 |
| 精度与显存占用 | 绘图模型、图片转换、提示词理解精度；用 CPU 处理图片 |
| 重复出图与内存占用 | 复用节点结果、保留数量、内存清理门槛；边计算边搬运模型 |
| 兼容性与结果复现 | 改善显存不足报错、尝试加快部分模型、尽量复现结果、内存传输和模型读取方式 |
| 过程预览与插件排查 | 过程图预览方式和大小；停用插件节点排查报错 |
| 激进提速 | 关闭/全部/自选；从当前 CLI 读取实际 `PerformanceFeature` 枚举 |

未检查时只保留原六项基础设置的兼容路径。新增非默认参数需要主动「检查环境」核实；不支持或能力已过期时明确拒绝启动，不丢弃参数。命令显示采用参数数组的等价 PowerShell 表达，不执行任意 shell 字符串。

「检查环境」使用指定 Python，读取版本、Torch/CUDA、显存、可选注意力依赖、磁盘与 `pip check`。探针对 `comfy/cli_args.py` 做 AST 读取，不执行该文件；记录参数、fast 枚举与 SHA256。能力绑定本体目录、Python 文件和 CLI 哈希，变更后须重新检查。可选依赖存在仅表示能够发现该包，具体 GPU、Torch、模型兼容性仍以实际启动为准，不自动安装。

截图中的「使用共享显存」没有已核实的原生对应项，因此未添加同名开关。智能显存管理、动态显存与 mmap 各有自己的含义，不代替驱动层设置；本轮不修改驱动或注册表。

「停止」仅针对当前工作台实际持有的子进程；重启后保存的 PID 是历史记录，外部启动的 ComfyUI 不提供停止按钮。日志记录工作台启动的进程；「连接」显式检查服务，「打开 ComfyUI」打开原生界面。

## 工作流、AI 与 MCP

「工作流与 MCP」左侧保留导入、预检、导出及工作流列表，右侧放 AI 工作流助手和绘图 MCP。助手可以选择已有工作流为基础；生成候选后，主动采用时再次预检，采用不会自动出图。

基础工作流与明确选择「新建」都会随页面草稿保持。编写与采用互斥，等待旧候选预检时不能并发编写并丢掉新候选。

MCP 使用工作台原有服务、令牌与 9 个工具。专用开关只提交 `mcpEnabled`，保留公共 AI 模型、密钥及启用状态；同步公共设置草稿中未修改的 MCP 值，保留明确不同的待保存选择。支持导出 stdio 客户端 JSON、复制当前会话的 HTTP 配置。HTTP 端口可能随工作台重启变化，长期连接使用导出的 stdio 配置。

模型、插件、下载与快照机制见 [运行与资源管理](workbench-drawing-manager.md)。快照仍是 Git/选定配置与依赖清单，不是完整 Python 环境备份。
