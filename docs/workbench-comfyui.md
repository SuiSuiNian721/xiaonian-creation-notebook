# ComfyUI 绘图模块

绘图最初开发于 `feat/comfyui-drawing-complete`，现纳入统一工作台。0.6.0 新增运行设置、诊断、预检、模型/插件、下载及快照管理，入口与边界见 [运行与资源管理](workbench-drawing-manager.md)，最新包和验证见 [0.6.0 验证记录](workbench-drawing-manager-verification.md)。

## 使用

1. 在工作台添加「角色绘图」，打开「接入配置」，点击「检测本机 ComfyUI」，核对目录并保存。可先填写 ComfyUI 本体或便携包根目录再检测；不依赖任何特定启动器。远端服务也可直接填写服务地址后连接。
2. 返回「绘图」点击「连接」。服务未运行时先点击「启动 ComfyUI」，稍后连接。「打开 ComfyUI」通过默认浏览器打开原生节点编辑器。
3. 「工作流与 MCP」支持导入 JSON，也可扫描配置的本地目录。检查通过后直接进入绘图页并选中该工作流；修改提示词、尺寸、采样参数，搜索选择 LoRA 和权重，按需上传参考图，再点击「生成图片」。导入本身不提交生成任务。
4. 在「工作台设置 → 共用 AI 连接」选择 Codex 桥接或 OpenAI 兼容 API，填写配置、勾选启用并保存。Codex 复用本机 CLI 登录与默认模型；兼容 API 的 Base URL 通常以 `/v1` 结尾。保存与测试连接是两个独立操作。
5. 在绘图页展开「AI 工作流助手」，输入要求，可基于当前工作流继续修改。候选先显示说明，点击「采用工作流」才导入副本；采用后仍需主动点击生成。
6. 外部 AI 接入：在公共设置勾选「启用 MCP」并保存，展开「MCP 接入」导出客户端 JSON，添加到支持 stdio 的 MCP 客户端。工作台应保持运行。stdio 桥每次读取当前端口记录，工作台重启后仍能重新连接；HTTP 配置也可复制，但随机端口重启后可能变化。

## 公共连接与 MCP

公共配置位于工作台自己的 SQLite，保留密钥的空输入与显式清除操作分开。各模块通过 `ModuleContext.ai` 或同源 `/api/ai/chat` 使用连接。角色卡的接入入口会跳转到公共设置；旧工作台中的独立卡片配置在首次使用时保留兼容，保存公共配置后统一切换。

MCP 使用带令牌的本机 Streamable HTTP 与附带的 stdio 桥，提供 `comfy_status`、`comfy_connect`、`comfy_nodes`、`comfy_workflows`、`comfy_workflow_get`、`comfy_workflow_import`、`comfy_generate`、`comfy_job`、`comfy_cancel`。生成必须使用唯一 `requestId`，重试沿用原值；只操作工作台自己的任务。MCP 默认关闭。

## 工作流与任务

绘图模块沿用工作台外壳，提供绘图、工作流、接入配置与运行记录。用户主动连接现有 ComfyUI，导入 API JSON 或普通工作流 JSON，按节点编辑提示词和参数，上传参考图后提交任务。工作流保存在工作台资料库，导入不改原文件。

普通工作流通过附带的 comfy-cli 1.17.0 转换器和 ComfyUI 实际节点定义转换，复用已有 ComfyUI 的 Python，不向其环境安装包。无法可靠转换的节点报错并保留原文件，可改用 ComfyUI 导出的 API JSON。

新版节点的 COMBO、动态选项分支、可增减输入组及 MatchType 连接按实际定义检查。例如 Qwen 2.1 文生图的空 `images` 组合法，保存图片的 `format.bit_depth` 属于所选格式的子参数。不能核实的自定义控件顺序仍会单独提示，不将它等同于模型或节点缺失。

已有 LoRA、参考图与尺寸字段直接呈现在绘图页。模型与文本编码器来源唯一时，可额外添加多项 LoRA，设置模型权重和文本权重；仅模型加载器不显示文本权重。额外设置只应用到本次任务副本，不覆盖导入文件。

可确定采样入口的 Qwen 2.1 工作流可直接增加参考图，默认输出尺寸跟随第一张参考图；参考图处理尺寸仍由节点的 `resolution` 控制。选择「使用宽高设置」则保留原来的尺寸路径，可能改变构图。后续采样阶段保留原有连接；跟随参考图时通过批量潜空间节点保留张数。其他工作流使用自身已存在的参考图输入，复杂分支可在原生 ComfyUI 中连接后再导入。

切换工作流和断线重连会保留参数草稿。无法确认某项附加设置时保留草稿并提示处理，不静默移除；待核对任务始终使用当时的完整参数，包含 LoRA、参考图与尺寸模式。

任务先持久化再提交；每次提交使用唯一请求标识，超时保持待核实，不自动重交。任务固定提交时的服务地址、工作流、参数与角色。进度只取自 ComfyUI 的 WebSocket 或真实队列；结果通过历史接口确认并由同源图片接口展示。取消使用 `/api/jobs/{id}/cancel`，只指定当前任务并等待实际状态；旧版服务若不支持此接口，会提示前往原生 ComfyUI 取消，工作台继续跟踪结果。应用关闭后不终止外部 ComfyUI；重新连接后恢复任务查询。

作品保存至工作台的数据目录，并可按配置复制至作品目录；文件采用唯一名称，绝不覆盖已有作品。额外作品目录复制失败会保留工作台内的图片并显示提示，可通过“保存图片”手动导出。记录原始任务、参数与输出文件，关联提交时的角色。

启动按钮仅使用指定 ComfyUI 的现有 Python 和 main.py，以本机回环地址启动；现有服务可直接连接。不会自动安装模型或节点。

检测会核对 `main.py`、`server.py`、`nodes.py` 和 `comfy` 文件夹，不把普通 Python 项目或启动器 EXE 当作 ComfyUI。本地目录检测与在线服务连接分开；连接通过 `/system_stats` 和 `/object_info` 检查实际 ComfyUI 服务。保留已填服务地址、作品目录和工作流目录；空值采用 ComfyUI 默认路径。Python 优先使用该安装自己的虚拟环境，再查找便携包的嵌入式 Python。已知整合包位置仅作为候选，不读取启动器设置。

验证覆盖假服务协议、真实 ComfyUI 连接与任务、断线重启、取消隔离、输出归档、角色归属、表单草稿及桌面明暗与小窗口界面。详见 [本次交付验证记录](workbench-comfyui-verification.md)。
