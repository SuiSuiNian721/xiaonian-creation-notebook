# 沉浸模式与陪伴界面适配

0.10.1 面向桌面端；手机适配暂不纳入。

## 操作

虚拟陪伴工具栏、角色卡作品编辑页都有「沉浸模式」。进入后仅保留紧凑的返回/全屏栏，工作台侧栏、顶栏和模块外层标题、页签隐藏，主体使用整个窗口的剩余空间。

- F11：进入沉浸全屏，或在沉浸中切换全屏。
- Esc：退出全屏和沉浸，恢复当前工作台模块。
- 「返回工作台」与 Esc 等价，不导航到首页。

布局变化不移动 iframe，也不重新挂载模块。写卡器未保存的正文和聊天草稿保持原样。原生陪伴视图与写卡 iframe 获得焦点时，同一组快捷键仍然生效。

## 实现与边界

`desktop/workbench-immersion.cjs` 管理真实窗口全屏、根页面 IPC 和获准子视图的快捷键。全屏请求串行，期间合并最新意图；Windows 的 enter/leave 事件会先于 `isFullScreen()` 更新，因此按事件种类确认，在微任务中推进后续请求。关闭后排队的回调不再操作窗口。

根 preload 只暴露沉浸设置、状态和订阅接口；仅根 WebContents 的 mainFrame 可直接调用。网页控制器 `public-workbench/immersion.js` 切换布局和恢复焦点，不重载编辑器。网页独立访问时有浏览器全屏回退，实际验收以 Windows Electron 为准。

陪伴首页和设置首页由平台实现；具体设置控件复用兼容运行端，统一字体、颜色与常用中文提示。运行时清空 `preset-*` 选择、过滤示例目录并禁止示例查询，不删除安装文件、不改写用户角色卡。尚未提供个人模型，本次只能验证空舞台与保留个人模型的契约，真实模型效果待文件到位后验收。

源码检查产物保存在独立的 `qa/companion-immersion-final`，0.10.1 包内复验在 `qa/companion-stdio-packaged`。通过本地 SSE 测试服务验证原生聊天控件与 AI 桥，并检查 15 个原生子页、无示例模型请求、两模块沉浸、窗口全屏、原生/iframe 焦点及正文与聊天草稿保留。

本轮源码验证：`npm test` 共 344 项，340 项通过、4 项现有真实 Python 环境检查跳过，0 失败，记录在 `qa/companion-stdio-fix/unit-all.log`。沉浸控制器 21 项、模型策略 3 项、断管与启动器 4 项均通过；0.10.1 打包程序的真实 Electron QA 15 组通过、退出码为 0，错误与示例模型资源请求均为空，正文与聊天草稿前后一致。声音、视觉和真实个人模型渲染未在本轮实际配置验收。

0.10.1 修复临时启动终端结束后，陪伴日志收尾触发 `EPIPE: broken pipe` 弹窗的问题。启动器使用独立子进程和直接继承的日志文件句柄；主进程启动时处理 stdout/stderr 的断管事件，不影响其他错误的上报。新增回归验证关闭两条输出管道后继续完成收尾，以及启动器退出后子进程仍能记录日志并保留隔离环境。

候选包由干净的 `8b6e623` 构建，94 个运行文件的包内 SHA256 与源码、构建记录一致，包含新增 stdio 防护。构建记录位于 `dist-workbench-companion-immersive/build-record.json`。

真实预览使用修复后的启动器，启动终端结束后仍正常运行；关闭时进程退出，日志包含 `[FileLogger] File closed successfully`，两路日志没有断管或未捕获异常，再次打开为 0.10.1 且运行状态正常。记录为 `qa/companion-stdio-fix/preview-close.json` 与 `preview-reopen.json`。这条独立进程关闭路径没有取得退出码，退出判断来自进程结束及日志收尾；包内 QA 的退出码单独由父进程取得。
