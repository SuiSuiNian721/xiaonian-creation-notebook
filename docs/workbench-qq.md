# QQ 角色接入

QQ 是聊天前端。工作台的 QQ 模块用于扫码登录、绑定角色、设置响应范围，以及查看会话和管理记忆；没有聊天输入框。虚拟陪伴与 QQ 的绑定、对话、摘要和记忆分别保存。

当前已纳入 main 的源码候选。协议与状态已通过本地模拟验证，固定运行包已实际取得未登录二维码；真实账号扫码、私聊和群聊由念念后续验收。语音、表情、主动联系和托盘常驻没有启用。现有正式桌面包尚未重建，源码与运行包的状态分别记录。

源码、实际组件与真实客户端的验证范围见 [验证记录](workbench-qq-verification.md)。

## 使用流程

1. 添加并打开「QQ 对话」，自动扫描已有组件；采用后点击「保存组件位置」。没有可用组件时，从「资源安装」选择普通本地文件夹，查看清单并确认安装固定版本运行端。
2. 回到「连接与角色」，选择受管模式并扫码登录角色的独立 QQ。工作台显示实际账号后，再连接消息通道。
3. 从已有角色资料中绑定角色。修改顶部选角不会改变正在使用的绑定；受限角色卡须明确选择基础文字模式。
4. 填写允许私聊的 QQ 号和允许群号，保存规则；群聊必须 @ 当前机器人。配置工作台的 QQ「AI 接入」，然后开始扮演。
5. 使用自己的 QQ 与角色交流。工作台只查看记录和状态，可暂停、断开，或开始新故事。

角色卡支持基础文字字段、常驻与关键词世界书及常用宏。开场白用于新故事的初始场景参考，不自动发送。MVU、EJS、卡内脚本和前端状态栏不会执行；不支持的动态内容会在绑定时提示。

「连接已有网关」使用 OneBot v11 正向 WebSocket，需要分别填写地址、令牌和预期机器人 QQ 号。工作台只连接，不接管该网关，也不提供它的扫码页面。旧 `F:\QQ` 的反向地址不能直接当作正向地址。

## 记录与记忆

会话按账号、绑定角色、私聊或群聊、对端及故事隔离，群成员保留自己的身份。手工记忆可选择来源消息、编辑和删除；删除记忆不删除原聊天。开始新故事保留历史，并取消同一会话范围内尚未完成的旧生成。

「人设与记忆 → 记忆」还会自动保存当前会话摘要、对象特点、共同经历与关系、计划与待办。同一角色实例中，同一联系人的明确现实记忆可跨普通会话延续；剧情关系留在原故事。已有本机确认聊天在连接时自动补整理，暂停回复也可进行，不会为此发送消息。来源、纠正与延续设置见[记忆说明](workbench-character-modes.md#记忆怎样工作)。

回复区分生成、发送中、网关确认、明确失败和结果未知。网关确认不代表对方已读。发送超时或掉线可能已经送达，因此不会自动重发；未确认回复不作为已经说过的话进入后续上下文。

页面刷新或切换模块不停止角色。显式暂停会取消旧生成；完整关闭工作台会停止自动回复、断开消息通道，但保留 QQ 登录端。重开时核对并接回原后台进程，回复仍保持暂停，验证连接后可继续扮演。退出、睡眠或关机期间工作台不会生成或发送回复，也不会补发关闭前取消的回复。

「断开连接」只断开工作台，保留 QQ 后台。「停止 QQ」、停止或移除对应实例会结束受管登录端，但保留账号资料，下次可能需要扫码。接入配置未变化时保存不打断连接；无效修改先报错，有效的实际变化才会停止原登录端。已有外接网关不受工作台进程管理。

## 组件与资料

「QQ 组件」支持首次自动查找、重新扫描和选择目录查找，选中候选只填入位置草稿，保存前会重新校验。查找不读取或导入旧 QQ 的账号、令牌与登录缓存。其他模块使用相同发现机制，见 [本机环境自动查找](workbench-environment.md)。

- 固定组件：NapCat `4.18.42` 的 Windows Node 包，下载后核对发布 SHA256，解压至所选位置的版本目录。安装不会启动 QQ。
- 配置和业务数据：工作台资料目录的 `data\qq`。账号槽位的 QQ 数据与 NapCat 工作目录相互独立，不导入旧 Demo、Aurora 或 `F:\QQ` 的资料。
- 受管运行端显式使用独立目录和本机回环端口。WebUI 与 OneBot 的令牌分别生成，不出现在界面或角色导出中。配置文件按本机运行需要保存，没有宣称已经加密。
- QQ 由独立后台进程托管，通过带随机密钥的本机 IPC 管理自己创建的子进程。后台存活期间端口不变；窗口重开不覆盖原管理、OneBot 或设备资料。进程归属记录保存在账号槽位内，记录不可验证时不会另开第二份 QQ，也不会按保存 PID 盲目终止进程。
- 模型使用工作台的全局或 QQ 模块覆盖，不额外维护模型密钥；QQ Codex 请求使用独立的纯文本进程，关闭本机工具、用户规则、MCP 和扩展。

NapCat 的 [Limited Redistribution License](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/LICENSE) 限制商业用途。工作台不把 QQ 本体和登录资料打入应用包；商业发行前须确认相应授权。

## 分支预览与检查

在 PowerShell 7 中运行分支根目录的 `Start-QQPreview.ps1`，会打开 QQ 管理页，资料保存在本分支 `artifacts\qq-preview-profile`，不使用正式工作台资料。

```powershell
Set-Location -LiteralPath 'E:\智能，生命。\AI-未来工作台\分支\ai-future-qq-research'
.\Start-QQPreview.ps1
node --test 'tests/qq-*.test.mjs'
```

开发预览需要已有 Electron 开发运行时；本机默认复用项目现有的构建工具。`AI_FUTURE_ELECTRON` 可指定其他兼容的 Electron。已准备的桌面包使用包内 Electron。

`tools/qa-qq-runtime.mjs` 使用固定安装包缓存，在全新资料目录中验证未登录启动、获取二维码与停止，结果不保存二维码内容。`tools/qa-qq-ai.mjs` 单独验证实际 Codex 文本调用；它会使用本机模型额度，不在打开页面时自动运行。
