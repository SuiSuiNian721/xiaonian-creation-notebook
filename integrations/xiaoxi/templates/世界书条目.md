# 世界书条目写作模板

一个条目 = 一个可独立触发的事实单元。宁小勿大：触发精准的短条目，胜过包罗万象的长条目。

## 正文（.md）写法

- 只写**事实**：设定、规则、地点、人物关系。不写创作意图和注释。
- 一段一个主题；条目内用短句陈述，避免叙事散文。
- 涉及数值/等级/时间线时写明确值，不写"很强""很久"。
- 条目之间不互相复制内容；共用事实放独立条目，靠共同触发词一起命中。
- 玩家姓名写成字面 `{{user}}`，不提前换成创作者称呼；`{{char}}` 只指当前角色，固定 NPC 名照设定保留。完整宏规则与适用范围见 `workflow/世界书写入指南.md`。

## 侧车（.yaml）要点

- `keys`：角色会自然说出的词才算好触发词（地名、人名、专有名词）；别用"的""了"这类必中词污染。
- `secondary_keys`：需要两词共现才注入时用，降低误触发。
- `constant: true`：每轮都注入的核心规则才用；常量条目计入每轮 token，保持极短。
- `insertion_order`：数字小的先插入；同主题条目用相邻数字便于维护。
- 人物类条目建议加 `name` 方便在工具里识别。

## 检查项

- [ ] 触发词在正文里确实出现（否则命中后模型看不到对应上下文会困惑）。
- [ ] 常量条目合计长度可控（先算 token 再决定常量化）。
- [ ] 没有把 description 已有的内容重复一遍。
- [ ] 玩家姓名使用 `{{user}}`，没有误替换固定 NPC、UID、变量路径或文件名；固定姓名例外已经单独确认。
- [ ] 使用的宏位置与变量来源正确；扩展宏和 EJS 已说明运行时依赖。
