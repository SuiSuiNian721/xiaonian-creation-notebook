# 引导式制卡工作流 · 说明

让制卡助手带用户**一步步**做卡：你每次只加载“当前这一步”的指令，减少上下文占用。灵感来自 ST 预设的“模块开关（enable/disable）”思路，落地为工作区的**文件 + 状态 + 调度约定**。所有文本本项目原创。

## 三件套

1. **模块工作模式文件**（`workflow/`）：每个制卡步骤一份，写清“这步干什么、怎么引导、产出到哪、完成标准、红线”。你进入某步时**只读那一个文件**。
2. **进度状态**（`cards/<卡>/.card/workflow.json`）：记当前 `stage`、已完成 `done`、引导阶段定的 `plan`、各模块产出 `artifacts`。由受控工具管理；studio 不再提供独立制卡向导面板。
3. **调度约定**（见 `AGENTS.md` 的「引导式制卡工作流」节）：你开工时读状态 → 只读当前模块 → 引导与整理草稿 → 用户确认 → 写入与检查 → 更新状态 → 提示下一步。

## 引导人格

`workflow/助手共用规则.md`——贯穿全程、跨卡类型共用的工作规则；当前人格由程序提供。

## 轻量原则（先看这条）

现在的模型已经能很好地演绎人格，**这些模块给的是判断依据、协作步骤、示例和产出落点，不是必须逐条填满的模板**。模块中的研究样本只用来解释怎样取舍，未经用户确认不得写进卡的正式设定。

制卡器右侧「写作参考」读取 `docs/写作参考/` 的创作者版 Markdown：按当前模块展开更完整的自然语言说明。角色卡与世界观卡的技术模块共享 `docs/写作参考/共用/` 中同主题的说明；你仍只读当前 `workflow/<stage>.md`，不会因为用户打开参考页而加载整套长文进对话。

- 写到**够具体、能演**就行，**不强制结构、不限条数**——该详细处详细，能一句带过就一句带过。
- 模块里的"几块 / 几件事"只是**思考角度**，不是必填表格；用不上的直接跳过。
- 助手的职责是**提醒你别写空泛标签、别落八股**，不是逼你把每个空格填满。
- 工具型模块（世界书 / MVU / 运行时增强 / 状态栏 / 小手机 / 同层UI / 质检 / 生成成品）主要由你运行命令，不要求用户手写。

## 按卡类型分轨（横向拓展）

不同卡走不同流程。`00-引导`（共用）先判卡类型，再分流到对应轨道目录：

| 轨道 | 目录 | 适用 | 状态 |
| --- | --- | --- | --- |
| 角色卡 | `workflow/角色卡/` | 围绕一个/几个角色展开的卡 | ✅ 已实现 |
| 世界观卡 / 场景卡 | `workflow/世界观卡/` | 主体是世界、场所、设定而非某角色 | ✅ 已实现 |

共用文件留在 `workflow/` 根：`说明.md`、`助手共用规则.md`、`00-引导.md`、`世界书写入指南.md`、`预设制作规则.md`、`MVU共用规范.md`。两轨技术模块以共用规范统一职责、接口和验收，轨道中只保留场景差异。

## 世界书是跨步的（没有独立模块）

**所有设定内容一律写进世界书**——世界观、运转规则、人设细节、NPC、地点、物品、关系，全由触发式或常驻条目承载。因此**不设独立的世界书模块**——

- 每一步先在对话中形成完整待确认稿：正文、条目划分、触发式或常驻选择、同名 `.yaml` 的 keys/灯色/顺序。**用户明确确认后**才写入世界书；未确认时不得创建或覆盖正式条目。
- **卡身只留"演"所需的最薄锚点**：开场白（first_mes）+ 一两句角色自述/语气（description），**不塞设定**；设定查世界书。
- **MVU 按职责协同**：世界书提供规则与状态回流，框架保存状态，Zod 约束结构；需要计算时加独立脚本，需要显示时选择界面与正则。具体边界见 `MVU共用规范.md`，不强制所有卡都安装显示面板。
- 写法、灯色、触发词与评估的统一口径见 `workflow/世界书写入指南.md`；任何一步需要查世界书怎么写时读它（共用参考，不占模块步）。
- **修改模式**里仍可随时浏览 / 编辑世界书条目（层次树的「世界书」节点），不受本约定影响。

## 状态文件格式（`cards/<卡>/.card/workflow.json`）

```json
{
  "stage": "00-引导",
  "done": [],
  "plan": { "cardType": "", "concept": "", "worldview": "", "outline": "", "modules": [] },
  "artifacts": {},
  "updatedAt": ""
}
```

- `stage`：当前所在模块。引导期为 `00-引导`；分流后为 `<轨道>/<NN-名>`，如 `角色卡/02-角色`。
- `done`：已完成模块列表。
- `plan.cardType`：卡类型（`角色卡` / `世界观卡` / …），决定走哪条轨道。
- `plan`：引导阶段产出——卡类型 / 一句话核心 / 世界观摘要 / 大纲 / 要走的模块清单。
- `artifacts`：各模块产出的位置或摘要（如 `{ "角色卡/01-世界观": "src/worldbook/世界/001-*.md" }`）。

## 省上下文铁律

你一次**只读当前 stage 那一个模块文件**（+ `助手共用规则.md` + `workflow.json` 状态），当前人格由程序提供；**不预读后续模块、不预读其他轨道**。`stage` 直接当相对路径用：读 `workflow/<stage>.md`（如 `workflow/角色卡/02-角色.md`）。整理稿得到用户明确确认、完成写入与检查后，才算做完并进入下一步。

流程结构与"模块 = 按需加载"的思路，借鉴自公开的 ST 制卡预设范式；**所有文本（小汐人格、各模块指令）均本项目原创，不复制任何第三方预设的人设或措辞**。原版那些专有叫法（如"调色盘 / 三面性 / 二次解释"）已在本工作流里改写、整合为自己的表述（见 `角色卡/02-角色`）。
