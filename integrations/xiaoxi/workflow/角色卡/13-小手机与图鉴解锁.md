# 模块 13 · 小手机与图鉴解锁（角色卡 · 按需）
> 概括：按需。挂外置手机扩展做交互界面；图鉴/CG 收集是手机里的 app：清单 + 本地存档 + 好感门槛 + 面板。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
12 之后。需要手机或图鉴时做；否则按计划进入下一个未完成模块，不跳过已选的 14-重型同层UI。门槛变量由 06 定义。

## 小手机 = 外部扩展，卡只引用
- 手机本体是**外置扩展**（tavern_helper 的 import 角色脚本），不是卡正文。把扩展 URL 写进定义 JSON 的 `imports`，由 `node tools/mvu.mjs gen … --card <卡>` 生成角色脚本对象落进 extra.json。
- 装没装、好不好看、能不能联网加载，**完全取决于用户环境**，必须真机验收。

## 图鉴 / CG 解锁配方（三层，照参考卡反推的公开做法）
1. **数据层**：门槛用 MVU 变量（如 `stat_data.关系.好感度`），模型每轮 JSON Patch 更新；手机从好友/联系人数据读 `好感度`。**别把门槛硬编码进界面**。
2. **逻辑层（角色脚本内）**：
   - `CG_LIST`：角色 → 场景 → 张数 的清单；`CG_BASE_URL` 指 https 图床，按名字拼路径。
   - 当前剧情解锁保存在聊天/MVU 状态中；跨档成就可另用带卡片命名空间的 localStorage。界面偏好、资源缓存与解锁状态分开，不承诺浏览器缓存随聊天回滚。
   - `unlockCG()` 在剧情走到对应场景时记入；"一键全解锁"要求好感度 ≥ 门槛，不足就按钮置灰。
3. **呈现层**：手机内图鉴 app；聊天出图由 11 的注入正则负责。两者读取同一权威解锁状态。

> 不挂手机时可用 14 的同层画廊，沿用选定的状态归属。

## 硬规矩
- 明确解锁数据属于当前聊天还是跨档成就；门槛读取 MVU，图床用 https。
- 角色脚本结构齐 `name/type/content/button/export_with`；import 只 https；用 `registerMvuSchema` 必须 import 且调用（diagnose 会查）。
- 脚本里读变量走 `stat_data.` 前缀与 `_.get` 防御；跨脚本接口用 `initializeGlobal` / `await waitGlobalInitialized`。

## 产出落点
- 手机与图鉴逻辑：`src/extra.json` 的 `extensions.tavern_helper.scripts`（角色脚本）。
- 门槛变量与更新规则：06 的 schema、08 的更新规则，不重复造。
- 聊天出图正则：11 的 `extensions.regex_scripts`。

## 助手怎么做
1. 先定要不要手机、图鉴清单有哪些角色/场景/张数、门槛变量与阈值。
2. 生成角色脚本（imports + 图鉴逻辑骨架）落 extra.json；清单与样式由用户补。
3. 跑 diagnose 看「角色脚本」「运行时接线」；按硬规矩自查。
4. 明说：手机与图鉴**只能真机验收**，localStorage 换浏览器会重置。

## 先让每项解锁有故事理由

询问用户图鉴想保存什么，以及玩家为何会打开它：是回看共同到过的地点，还是查看确实发现过的插画？例如「第一次与角色进入旧车站后解锁站台档案」，应说明这个事件怎样被记录、切换聊天后应不应该保留。界面按钮被点过不等于剧情里已经发现，浏览器缓存也不能作为解锁事实来源。

助手要把「当前聊天的发现」「跨档收藏」「图片缓存」分别列清。若用户选择跨档成就，提醒同一浏览器内可保留，但换设备、清理存储后无法自然同步。设计解锁门槛时先看 06/08 是否已有权威变量，不为手机另造一份隐藏好感度。图鉴清单、空状态与素材缺失时的文字都应可读。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
手机以 import 角色脚本挂上且 export_with 齐；图鉴三层齐（变量门槛 / localStorage 解锁 / 面板）；出图与隐藏正则成对；diagnose 无 error；已告知真机验收与 localStorage 局限。

## 红线
**不执行卡内脚本/HTML，只读分析 + 生成文本**；不写酒馆安装目录；不抄参考卡的专有界面、文案与图床清单（只取公开做法，散文与代码自写）；真机验收权留给用户。
