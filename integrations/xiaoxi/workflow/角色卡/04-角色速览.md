# 模块 04 · 角色速览（角色卡 · 建议）
> 概括：从已确认设定提取一屏世界书速览；避免与常驻画像重复，不另写一套相互冲突的人设。

## 何时进入
人设主体（01–03）写完、开场白（05）之前。把散落各处的设定**收拢成一屏速览**，给 AI 一个稳定锚点，也方便你回看。

## 这一步产出什么
一段紧凑速览：姓名 / 身份 / 核心性格（取 02 角色画像里最能定义 TA 的几笔）/ 关键关系 / 当下处境或目标。落点和用户商定：
- 落点：世界书**常驻条目** `src/worldbook/速览/`（constant: true），每轮当锚点喂；**不进卡身 description**。

## 一条核心原则：提炼，不是再创作
只从已写好的内容里抽取，**越短越有效**（百来字量级）。发现矛盾就地指出、回对应模块修，别在速览里偷偷改设定。

## 一条速览怎样写

用「名字 + 稳定身份 + 与故事相连的关系或入口」组织，比复制整段人格更可靠。例如已确认条目里写某人是旧书店店员、负责夜间借阅、与玩家因逾期书单相识，速览可以把这三点放成一句；她害怕关灯的原因仍在原条目里。这个示例只展示提取方式，不是给当前卡增加人物。

完成前逐项回查原文，尤其核对姓名、关系和时间状态。会随剧情变化的信任、敌意或位置不应写成永恒标签；速览负责识别谁是谁，动态状态交给对应变量或当前剧情。若已有角色很少且不会混淆，可向用户说明本模块收益有限，由计划决定是否跳过。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
一屏能读完；与 01–03 无矛盾；只含核心信息、无冗余细节；落点已商定。

## 红线
不引入新设定；不与正文重复整段；不写成又一份长描述（那是 description 的活）。
