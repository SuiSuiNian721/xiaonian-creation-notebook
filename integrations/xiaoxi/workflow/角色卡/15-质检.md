# 模块 15 · 质检（角色卡 · 必经 · 双门）
> 概括：生成成品前完成结构检查与静态诊断；核对引用、状态回流与显示隔离，构建和真机测试另行验收。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
所有需要的写作与增强模块（01–14）完成、打包之前。**两道门都过才放行**，缺一不可。

## 第一道门 · 结构 `check`
跑 `node tools/card.mjs check <卡名>`（或 studio 的 check 按钮）。它查的是**结构完整性**：必填字段是否为空（name/description/first_mes）、index.yaml 是否合法、世界书条目结构等。
**要求：错误清零。** 有错先回对应模块补，别带病打包。

## 第二道门 · 内容 `diagnose`
跑 `node tools/diagnose.mjs <卡名>`（或 studio 的「内容诊断」面板）。它查的是**内容质量**，9 项：基础字段、世界书健康、关键词冲突、token 占用、八股词、正则脚本、**运行时接线**（用了 `<UpdateVariable>` 却没人接管 / 缺变量回流条目 / 美化脚本 promptOnly 配反 / EJS 标签不配对）、**EJS 用法**（`getwi` 漏 `await` / `const` 接 `getvar` / 装饰器错位 / `@@preprocessing` 与 `generate_before` 混用）、**角色脚本**（tavern_helper 缺 name / 空 content / `registerMvuSchema` 没 import 或没调用 / import 非 https / button 与 export_with 不齐）。
处理原则：
- **错误（err）**：必须清零（如绿灯无 keys、泛词关键词、空 findRegex、EJS 标签不配对）。
- **警告（warn）**：逐条看过、能改就改、确属误报再说明保留理由（如常驻 token 偏高、未锚定的 `.*`、接线缺失）。
- **提示（info）**：参考，不强制。

## 助手怎么做
- 先 `check` 后 `diagnose`，把结构、引用与接线错误归回对应模块修复后重跑；文风提示只供作者判断，不擅自重写用户手写画像。检查 EJS 可达目标、原文保留和剧情/变量两端的状态回流。
- 不替用户判断"警告无所谓"——每条警告要么修、要么讲清为何保留。

## 把报错当作定位线索

例如世界书某条关键词太泛，可能导致每轮都加载一大段不相关人设；先查它会命中哪些自然对话，再决定改成更具体的称呼、拆条目或保留并说明理由。又如变量保存了但下一轮仍被忘记，应分别查保存结果、回流条目和叙事遵守情况，不靠加重提示词掩盖接线错误。

对用户亲手写的角色画像，只指出能定位的矛盾或空泛处，附原句与影响，不擅自改成标准化文案。完成时给一份能读懂的检查记录：哪些错误已修、哪些警告保留及原因、哪些体验仍待酒馆真机确认。这样下一次修改才知道从哪里继续。

## 完成标准
`check` 零错误；`diagnose` 零错误、警告逐条处理；改动后已重跑确认。

## 红线
两门未过不得进 16；**check/diagnose 通过 ≠ 真机验收**，别把"工具过了"说成"卡没问题"。
