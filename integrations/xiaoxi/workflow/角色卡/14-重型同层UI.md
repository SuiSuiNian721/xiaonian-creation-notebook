# 模块 14 · 重型同层UI（角色卡 · 按需）
> 概括：按需。整页同层界面：正文美化（模式A）与结构化主页/面板（模式B），和聊天在同一层里滚动，不是弹窗。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
13 之后、15-质检 之前。这张卡要**整页界面**（主页 / 面板 / 美化正文 / 同层画廊墙）时才做；纯文字或只要状态栏的卡跳过。

## 两种模式（选型）
- **模式A · 正文美化**：把模型输出的某段标签文本（如 `<story>…</story>`）渲染成漂亮排版。**两文件**：一条正则 + 一份 HTML。
- **模式B · 结构化整页**：模型按约定格式吐数据，HTML 解析后渲染成整页（主页 / 面板 / 画廊墙）。**三文件**：正则 + 世界书源文件（写清格式与触发词）+ HTML。
- 同层画廊墙（13 的图鉴不挂手机时的变体）按模式B 做；读取已选定的聊天解锁状态或跨档成就，不把资源缓存当剧情状态。

## 硬规矩（照公开自查口径）
- 正则匹配完整闭合标签，启用显示专用标志；捕获组或读取本条消息均可，按渲染环境处理转义与未闭合流式内容。
- 酒馆助手 HTML 可按本条消息读取数据，明确初始化与事件清理；布局适配容器，异常时保留可读正文。原生 EJS iframe 使用模板预渲染方案。
- **标签三处一致**：正则里的标签名 = HTML `messageText.match()` 里的 = 源文件里的。
- 模式B 源文件写清数据格式、触发条件以及与 MVU 更新块的先后顺序，不笼统禁止界面标签之后的变量更新。
- 剧情正文保留或转换成可读叙事送给模型；仅无剧情语义的控制信息可用 `promptOnly` 隐藏。不要删除承载唯一剧情内容的数据块。

## 产出落点
- 正则 + HTML：`src/extra.json` 的 `extensions.regex_scripts`（HTML 内嵌在 replaceString）。
- 模式B 源文件：`src/worldbook/<书名>/`。

## 助手怎么做
1. 先定模式A 还是 B、要哪几个页面；别默认全上。
2. 逐页给正则 + HTML（B 再加源文件）落进落点；HTML 只给能跑骨架，样式由用户调。
3. 跑 diagnose 看「正则脚本」「运行时接线」；按硬规矩逐条自查；确认标签三处一致。
4. 明说整页观感与真机生效**只能用户验收**。

## 从一页真实内容倒推界面

先请用户拿出想排成页面的一段内容，再判断模式。若只是调查手记需要标题、日期与段落，模式 A 已够；若要让玩家在主页查看地点、线索和解锁状态，才考虑模式 B 的结构化字段。示例字段由真实内容推导，不先画一整页空框再逼剧情填满。

检查一段很短的消息、一段很长的消息和标签暂未闭合的流式输出。界面无法渲染时仍要保留可读叙事；模型下一轮也应收到足够理解故事的文本。助手要逐项核对标签在源文件、正则和 HTML 中完全一致，并说明当前只能做静态接线检查，实际滚动、点击与窄屏阅读须真机验收。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
要做的页都有正则 + HTML（B 加源文件）；标签一致，显示保留原始消息，提示词保留剧情语义；diagnose 无 error，已告知需真机验收。

## 红线
**不执行卡内 HTML/EJS/脚本，只读分析 + 生成文本**；不写酒馆安装目录；不抄参考卡的专有界面与文案（只取公开语法事实）；真机验收权留给用户。
