# 模块 12 · EJS条件加载与多阶段（角色卡 · 按需，用 `ejs.mjs`）
> 概括：让剧情反过来改变设定：EJS 按变量决定这轮注入哪些条目 / 点亮哪些关键词 / 切换多阶段人设；不写任何文件级新内容。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
11 之后（或 MVU 组之后）。需要**条件加载 / 多阶段人设**时才做；纯静态卡跳过。

## EJS 是什么、边界在哪
EJS 由 **ST-Prompt-Template 扩展**在生成或渲染阶段处理；它与浏览器中的事件脚本有不同职责。
- 能做：按变量切换加载哪些条目、条件点亮关键词、按日期/楼层加载、渲染状态栏。
- 支持 JavaScript、JSON 解析和数组运算；本项目不执行卡内模板、不自动联网或安装依赖。
- "事件触发"属于 regex 脚本 / 扩展脚本，不是 EJS 的活。

## 两个常用件（`node tools/ejs.mjs controller|statusbar`）
- **多阶段人设控制器**：控制器条目设**蓝灯、顺序 100、不勾防递归**；正文用 `getvar` 读变量、按阈值 `await getwi('阶段条目')` 加载。被加载的**阶段条目必须设为禁用**（否则自己常驻），顺序 98~800。
- **`@@iframe` 状态栏**：正文顶部三行装饰器 `@@render_after` / `@@iframe 标题` / `@@if !is_user && !is_system`，模板阶段读取并转义变量，渲染到助手消息末尾、不发给 AI。原生 iframe 不假设有酒馆助手全局；需要实时订阅时用 11 的酒馆助手面板。

## EJS 硬规矩（写错就整条坏）
- `getvar('stat_data.属性.好感度')`——读 MVU 变量**必须带 `stat_data.` 前缀**；但 AI 的 JSON Patch path **不带**前缀。
- `getwi` **必须 `await`**；漏了会注入 `[object Promise]`。
- 装饰器逐行排在条目**最前**，中间**不能有空行**；`@@preprocessing` 不能和 `@@generate_before/after` 混用。
- 新控制器使用 `@@private` 隔离局部变量，可用 `const`；每个控制器读取自己的路径，不复用其他条目的同名值。静态引用必须能找到目标，版本号写正文而非引用名。

## 产出落点
控制器 / 阶段 / 状态栏条目：`src/worldbook/`（摆对灯色/顺序/禁用状态）。

## 从关系变化检查条件加载

先请用户指出角色在不同阶段究竟哪里会变：称呼、允许触碰的话题或愿意透露的信息可以变，稳定身份和已经确认的经历不应被控制器改写。例如信任建立前她只谈工作，之后愿意提一段旧事；两段内容都由用户确认，再让 EJS 根据当前状态选取。若阶段条目本身常驻，控制器再加载它就会重复甚至互相冲突，因此静态条目与按条件加载的条目要分清。

助手应先给用户看自然语言的「条件 → 载入内容」对照，再落模板。检查目标条目是否存在、变量路径是否与 MVU 结构一致，最后用阈值两侧的样本推演：每一侧到底会读到哪段设定。工具能发现部分语法错，真实模板结果仍须在酒馆中确认。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
