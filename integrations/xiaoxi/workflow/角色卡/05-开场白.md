# 模块 05 · 开场白（角色卡 · 必经）
> 概括：写对方看到的第一条消息（必填），另可加几条真正不同的备选开场供切换切入场景。

## 何时进入
人设与速览写完之后。开场白是 {{user}} 看到的第一条消息，**直接决定 AI 之后怎么演**。这是必填项（`check` 会拦空 first_mes）。

## 这一步产出什么
- **主开场**：`src/text/first_mes.md`（→ `first_mes`，必填）。
- **备选开场**（可选）：`src/greetings/NNN-*.md`（→ `alternate_greetings`，按文件名排序），给不同切入场景；要**真的不同**（不同时间线 / 视角 / 情境），不是换几个词。

## 三条原则（不必逐条凑，但别全缺）
1. **场景落地**：时间 / 地点 / 正在发生的事，给一两个具体感官细节，别空泛。
2. **角色在行动中登场**：让 TA"正在做某事"，自然带出 02 角色画像的语气，而不是静态自我介绍。
3. **给 {{user}} 留钩子**：一个明确的互动入口（一句话 / 一个问题 / 一个待回应的情境）。

语气 / 人称与全卡统一，全程别飘。

## 用第一幕而非简介起手

先确定玩家进入时正在发生的一件事，再让角色在行动中说第一句话。示例：「闭馆铃响了第二遍，她却把借阅册翻回第一页，指着你刚签下的名字问：‘这行字，是你写的吗？’」它给出地点、角色动作和玩家可回应的问题。示例不应移入用户卡；助手要问用户想要哪种张力，并以已确认人物语气写实际开场。

检查开场结尾是否留给玩家真正的选择。如果文本替 {{user}} 说出态度、接受任务或回忆一段未确认经历，先删去这些代行部分。备选开场不仅换天气，还要换互动关系或事件入口；如初见、共同处理失物、关系破裂后的重逢。用了 MVU 时，逐条把开场文字和初始状态对齐。

## 助手怎么做
- 先问：想让 {{user}} 从哪个情境切入？据此定主开场。
- 写完引导用户自查：有没有八股开场（"在一个……的日子里"）？钩子清不清楚？

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
`first_mes` 非空、场景+行动+钩子基本齐全；语气与全卡一致。

## 红线
**不替 {{user}} 说话 / 决定动作或心理**；不写与 01–05 矛盾的信息；不用八股开场模板；不剧透本应玩家探索的内容。
