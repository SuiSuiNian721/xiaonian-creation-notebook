# 模块 00 · 引导（构思 + 分流）
> 概括：先聊清构思、判断这是哪种卡并排好要走哪些模块；只出规划，不写正文。

## 何时进入

- 新建卡的起点；或用户想重新规划一张卡。
- 本模块**跨卡类型共用**：先聊清构思，再判断这是哪种卡，分流到对应轨道。

## 角色卡由什么构成（开场先给用户讲清）

一张角色卡 = 酒馆读的一份"角色档案"，由这几层拼起来，各管一件事：

- **卡身入口**：开场白与薄锚点；本项目完整画像和性格写入常驻世界书。开场属于聊天消息，不保证永远保留在上下文中。
- **世界书**：按需加载的设定抽屉——命中触发词才注入，省 token。角色在**特定场景 / 关系 / 过往**里才露出的侧面放这里（跨步写，不单独成步）。
- **MVU 变量**：跨回合记得住、会变的量（好感 / 状态 / 持有物）。性格随关系**变化的刻度**放这里。
- **EJS / 状态栏 / 小手机 / 同层UI**：运行时呈现——按变量决定这轮注入哪些侧面、把状态演给玩家看。是"演出来"，不是"写进去"。
- **预设**：玩家那边的提示词编排与参数，卡不内置；我们只保证卡内内容跟它配合得好。

一句话：**正文给底色、世界书给场景化侧面、MVU 给变化刻度、开场白给第一口的语气**——四样齐了角色才"活"。

## 怎么问（深入但有度）

- 每轮**最多两三个深问题**，问完就停，等用户答；不连环追问、不一次甩一张问卷。
- 问题要**逼出具体**：不问"她性格怎样"，问"她生气时第一句话会说什么、事后会不会后悔"。先给一个自己的示例启发再问，但不发改空的模板让 TA 填。
- 用户答"先这样 / 不知道"就**收下并记下待定**，往后用剧情补，不纠缠。
- 角色数量：默认**聚焦一个主角**；确需双 / 三主角才写两三个，配角一律走 NPC / 世界书，不抢主线篇幅。

## 世界卡开场提醒（分流到世界观卡时先说这段）

- 世界卡的**侧重**是：世界观、**具体运转规则**、**社会行为**、**普通人的生活方式**、**阶层划分**、**资源分配**——写"世界怎么转、人怎么活"，不是写某个人。
- **角色 / NPC 字段淡化甚至跳过**：这条轨不立主角；确需具体人物时写成触发式世界书条目（群体描述 + 示例剪影），不单独成步。
- 设定**全部入世界书**，卡身只留最薄锚点；写法见 `workflow/世界书写入指南.md`。

## 这一步产出什么

**不写卡的正文**，只产出**规划**（写进 `cards/<卡>/.card/workflow.json` 的 `plan`）：这张卡的**类型**、核心、世界观摘要、大纲，以及要走哪些模块。

## 研究记录怎么展开

开局先请用户描述最想保留的一幕，而不是要求一次交齐世界、角色和玩法。例如用户说「雨夜里会移动的车站」，先复述「车站是作品中心」这一暂定判断，再问玩家最想与谁互动、移动会改变什么。若重点是站里某位会反复遇见的工作人员，倾向角色卡；若重点是整座城市如何适应移动车站，倾向世界观卡。把判断依据说给用户听，允许对方纠正。

规划里要区分「已确认」与「待研究」。用户尚未决定车站移动的原因，就把原因记为待定，不为凑完整计划临时发明。模块选择也按体验取舍：需要跨回合记住站台位置才讨论 MVU；只是固定背景时先用世界书。向用户说明每个被选模块会解决什么问题，让计划像研究路线，而不是功能购物清单。

## 助手怎么做

1. **核心想法**：问用户——这张卡一句话是什么？（谁 / 在什么世界 / 和 {{user}} 是什么关系或冲突）。记为 `plan.concept`。
2. **判卡类型（分流）**：据构思判断这张卡属于哪一类，记为 `plan.cardType`——
   - **角色卡**（聚焦单个、或两三个角色的塑造）→ 走 `角色卡/` 轨道（本工作流已实现）。
   - **世界观卡 / 场景卡**（主体是设定、世界、场所而非某个角色）→ 走 `世界观卡/` 轨道（已实现）。**分流到这条轨时先给用户读"世界卡开场提醒"**（见下）。
   - 拿不准就复述判断依据让用户确认，别自作主张。
3. **世界观**：按卡类型控制深度，记为 `plan.worldview`。角色卡只记录理解角色所需的短背景，不在引导阶段展开地点、制度、历史或完整规则；世界观卡只记录起点，详细内容留给后续世界观模块逐步研究。
4. **大纲**：引导聊——开场情境、角色关系、想要的剧情走向与体验（日常 / 冒险 / 情感等）。记为 `plan.outline`。
5. **分析整理**：助手把聊的内容整理成结构化 `plan`，复述给用户确认。
6. **商定模块**（以角色卡轨为例）：必做 `01/02/05/15/16`；按需 `03/04/06/07/08/09/10/11/12/13/14`。和用户商定后写进 `plan.modules`（有序，值为 track 内模块名，如 `角色卡/02-角色`）。
7. **世界书跨步（重要）**：世界书**不单独成步**。需要进入世界书的设定先在当前模块形成完整待确认稿（正文 + 同名侧车建议）；用户明确确认后才写入。卡身只留开场白与一两句自述锚点，**不塞设定**。MVU 靠**世界书条目 + 角色脚本 + 正则**三件套协同，不写卡身。确认、写法与评估见 `workflow/世界书写入指南.md`（共用参考，不算模块）。
8. **落状态**：把 `plan` 写入 `workflow.json`，`stage` 设为 `plan.modules` 的第一个（角色卡通常 `角色卡/01-世界观`），`done` 追加 `00-引导`。

## 完成标准

用户认可 `plan`（卡类型 / 核心 / 世界观 / 大纲）和模块顺序；卡类型已分流到正确轨道。

## 红线

- 只引导和整理，**不替用户拍板设定**，也不替用户定卡类型（拿不准就确认）。
- 引导阶段不写 `src` 正文（避免没规划好就动笔）。
- 分流到世界观卡时，**必须先读"世界卡开场提醒"**再开始聊，别把角色卡流程硬套上去。
