# 模块 16 · 重型同层UI（世界观卡 · 按需）
> 概括：整页同层界面：世界地图 / 势力面板 / 编年史主页（模式B），或把某段叙述美化排版（模式A）。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
15 之后、17-质检 之前。要**整页界面**才做；只要状态栏的卡在 13 已够。

## 两种模式
- **模式A · 正文美化**：把模型输出的标签段（如 `<chronicle>…</chronicle>`）渲染成漂亮排版。两文件：正则 + HTML。
- **模式B · 结构化整页**：模型按约定格式吐数据，HTML 解析渲染成整页（世界地图 / 势力关系面板 / 编年史）。三文件：正则 + 世界书源文件（格式与触发词）+ HTML。
- 同层画廊墙（15 的图鉴不挂手机的变体）按模式B 做。

## 硬规矩
- 正则匹配完整闭合标签，勾"AI 输出、编辑时运行、仅格式显示"；捕获组或读取本条消息均可，明确转义与流式降级方式。
- HTML 按实际渲染环境初始化并清理事件，可捕获正文或读取本条消息；布局适配容器，异常时保留可读正文。原生 EJS iframe 使用模板预渲染方案。
- 标签三处一致（正则 / HTML match / 源文件）；美化只改显示。剧情保留或转为可读叙事，只有无剧情语义的控制信息才从提示词隐藏。

## 产出落点
正则 + HTML：`src/extra.json` 的 `extensions.regex_scripts`；模式B 源文件：`src/worldbook/<书名>/`。

## 先拿一页故事试版

若用户想展示城市地图，先问玩家在这页要解决什么：辨认当前位置、规划通行路线，还是回看已发现的势力？目标不同，字段也不同。只是把一段编年史排得更易读，模式 A 通常足够；需要地点状态、交互和解锁时，再做模式 B。不要先堆整页控件，再让模型凭空制造内容填满。

检查短文本、长文本、移动端窄屏和未闭合流式标签四种状态。若界面失败，剧情信息仍应能以文字读到；若地图数据是下一轮剧情唯一的地点来源，不能被 `promptOnly` 无条件抹掉。正则、源条目和 HTML 的标签及字段命名逐一对齐后，再交给真机验证显示与操作。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
页都有正则+HTML（B 加源文件）；标签三处一致；成对没配反；diagnose 无 error；已告知真机验收。

## 红线
不执行卡内 HTML；不写酒馆安装目录；不抄参考卡界面。
