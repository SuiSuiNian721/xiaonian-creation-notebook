# 模块 13 · 前端状态栏与出图注入（世界观卡 · 按需）
> 概括：把世界状态演给玩家看：局势/时间/资源条状态栏，以及把标签换成地图/插图/视频的注入正则。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
12 之后（或世界卡直接需要出图时）。要**变量面板**或**聊天里出图/出视频**才做。

## 状态栏三选型
1. MVU 占位符 + 成对正则（08 已给骨架）：最稳。
2. 整段 HTML 状态栏：显示端正则换完整 HTML 文档。
3. EJS `@@iframe`：最轻，样式自由度低。
世界卡常用显示项：时节 / 治安 / 粮价 / 阵营关系 / 所在地点。

## 出图 / 注入
- 模型吐 `<pic>图名</pic>` 一类标签，显示端正则用捕获组换 `<img src="图床/$1.webp">`；视频同理。
- 必配同 find 的 `promptOnly` 正则抹回传，否则模型会看见自己的图标签。

## 硬规矩
- 酒馆助手状态栏等待 MVU 后按所在消息调用 `Mvu.getMvuData({type:'message', message_id:getCurrentMessageId()})`，读取 stat_data，订阅更新后重渲染；原生 EJS iframe 则在模板阶段读取并转义，不混用这套全局接口。
- 成对正则别配反；勾"AI 输出、编辑时运行、仅格式显示"。

## 产出落点
`src/extra.json` 的 `extensions.regex_scripts`（在 mvu 已写入的 5 条之上追加）；EJS 路线条目入世界书。

## 从世界尺度选择显示项

先问玩家做决定前会查什么：当前时节、所在区域、港口是否封闭，可能比整张阵营关系表更有用。若要在聊天里显示地图，先列出确实拥有素材的地点，再约定标签与资源路径；没有图片时仍让玩家读得懂当前位置。显示数值应取自保存的世界状态，不另用界面颜色猜测局势。

挑三种消息做体验样本：普通叙事、状态明显变化、图像加载失败。助手核对显示端、提示词端和剧情文字是否分工清楚，尤其不能把地图标签中唯一的地点信息一起从模型上下文删除。静态诊断通过后仍需在目标酒馆检查窄屏布局和实际资源加载。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
显示端与 promptOnly 成对；出图有注入+隐藏；diagnose「正则脚本」「运行时接线」无 error；已告知真机验收。

## 红线
不执行卡内 HTML/脚本；不写酒馆安装目录；不抄参考卡界面。
