# 模块 15 · 小手机与图鉴解锁（世界观卡 · 按需）
> 概括：挂外置手机扩展做交互界面；世界卡的图鉴=地点/势力/物种/物品图鉴，靠好感或探索度解锁。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
14 之后。要**手机式交互**或**收集图鉴**才做；都不需要跳到 16 或 17。

## 小手机 = 外部扩展
手机本体是 tavern_helper 的 import 角色脚本，卡只引用：扩展 URL 写进定义 JSON 的 `imports`，由 `mvu.mjs gen … --card` 生成脚本对象落 extra.json。装没装、好不好看**只能真机验收**。

## 世界卡图鉴配方（三层）
1. **数据**：解锁门槛用 MVU 变量（探索度 / 声望 / 某阵营关系，见 08），不硬编码。
2. **逻辑（角色脚本内）**：清单与 https 图床；当前剧情解锁用聊天/MVU 状态，跨档成就可另用带卡片命名空间的浏览器存储。
3. **呈现**：手机内图鉴 app；聊天出图由 13 的注入正则负责。
不挂手机时可用 16 的同层画廊，沿用同一状态归属。

## 让发现过程决定条目

图鉴不只是列出所有地点。先问玩家在什么行动后才算发现：踏入旧城区、从居民口中听到传闻，还是读到一份档案？这三种情况代表不同知识层次，可以决定显示完整资料还是只露出名称。若世界有一座废弃车站，不应因为图片被缓存就算玩家已探索；发现状态应来自剧情或已确认的世界变量。

助手与用户先确定当前聊天的探索记录是否独立，以及哪些收藏允许跨档保留。图床素材、解锁门槛和界面展示各从同一份清单核对；缺图时提供可读名称与说明。手机扩展能否加载、点击和保存仍需用户在酒馆里实际验收。

## 硬规矩
区分当前聊天解锁、跨档成就与资源缓存；门槛读取 MVU，图床用 https；角色脚本结构齐 name/type/content/button/export_with。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
手机以 import 脚本挂上；图鉴三层齐；出图与隐藏正则成对；diagnose「角色脚本」「运行时接线」无 error；已告知真机验收与 localStorage 局限。

## 红线
不执行卡内脚本；不写酒馆安装目录；不抄参考卡清单与文案。
