# 模块 10 · MVU变量更新规则（世界观卡 · 按需）
> 概括：MVU 第三件：[mvu_update] 规则条目——教模型每轮用 JSON Patch 描述世界刻度怎么变；patch path 不带 stat_data 前缀。

共用技术口径见 `workflow/MVU共用规范.md`；变量定义、计算职责、回流、显示与验收按该规范执行。

## 何时进入
09 之后。

## 这一步产出什么
世界书条目 `[mvu_update]变量更新规则`：
- **何时更新**：哪类事件推动哪个量（冲突/丰收/政策/季节更替）。
- **怎么更新**：JSON Patch 示例；**path 不带 `stat_data.` 前缀**。
- **幅度与边界**：单次变化合理范围；派生量禁改。

- **条目配置**：`[mvu_update]变量更新规则`，确保更新端能加载；插入位置与深度按实际预设验证，顺序 200 不代替触发条件。

## 研究样本：让变化符合世界尺度

若一处仓库失火，先问它影响一个街区的存货，还是足以改变整座城的粮价；若连续数周运输中断，才可能触及更大范围的资源变量。用「事件发生在哪里、持续多久、谁已经知道、哪项状态直接受影响」组织规则，比一句「根据剧情合理变化」更可执行。示例事件只用来校准尺度，不擅自写入用户设定。

至少试三种样本：有变化、无变化、局部事件但某项全局值不应变化。每个例子都核对 08 的字段名、09 的初值与世界书里的制度边界。JSON Patch 写入路径按本卡协议，不把读取时的 `stat_data.` 前缀带进去；规则不能要求修改派生字段。

## 助手怎么做
- 规则写成"事件 → 操作"短句清单 + 一个完整 patch 示例；字段必须都在 08 的 schema 里。
- 世界刻度的变化要能和 02 运转规则、04 经济的设定对得上。

## 引导与确认流程

1. 先用大白话说明本模块要解决什么、结束时会得到什么，不从工具命令或术语开始。
2. 读取已有 `src/` 与已确认计划，跳过用户已经回答的内容；每轮最多追问两三个与当前缺口直接相关的问题。
3. 用户卡住时给 2–3 个方向，并说明各自会怎样影响体验；示例必须标明是启发，不得自动进入正式内容。
4. 动手前在对话中展示完整待确认稿：正文或结构、目标文件、世界书条目与侧车配置、脚本/正则改动及外部依赖。明确列出仍属待定、不写入的内容。
5. 只有用户明确确认当前稿可以写入后才修改 `src/`。涉及世界书时同时遵守 `workflow/世界书写入指南.md`；用户要求调整时先改草稿并重新确认受影响部分。
6. 写入后按 UTF-8 回读，运行本模块规定的检查，汇报实际文件和未验证项；未确认、未写入或检查失败时不得标记完成或推进 stage。
## 完成标准
规则条目落世界书；patch 示例与 schema 一致；diagnose「运行时接线」无 error。

## 红线
不写卡身；不执行卡内内容。
