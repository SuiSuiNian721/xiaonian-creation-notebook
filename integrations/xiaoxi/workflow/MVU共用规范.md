# MVU 共用规范 · 角色卡与世界观卡

两轨共用技术依据；进入 MVU、EJS、界面或质检模块时一并读取。模型会话桥自动附带本文件。它统一技术口径，不规定世界题材、角色数量、玩法或文风。

## 职责与数据流

1. 世界书保存设定、模型更新规则和输出协议；卡身只留开场与薄锚点。
2. 定义 JSON 是本工具生成 schema/初值/面板字段的共同输入。Zod 检查类型、默认值和范围；不把整段脚本发送给模型。
3. MVU 解析更新指令并保存消息状态。默认生成器使用 add/replace/remove/move 的 JSONPatch 路径；现有卡若用 delta/insert 等另一方言，沿用并核对实际框架支持，不能混写。
4. 需要派生数值时编写独立计算脚本。`_` 命名不会自动产生公式；明确输入、输出、事件时机和唯一写入者。同一状态重复处理不得重复扣款或升级。
5. EJS 读取状态、筛选需要的规则；界面读取状态并展示。界面中的操作须经明确写入入口，不维护第二套权威数值。

同步修改链：变量定义 → schema → 初值 → 更新规则 → 状态回流 → 计算脚本 → 面板。改 schema 前评估旧聊天字段保留与迁移，不承诺直接重载即可兼容旧档。

## 初始值、回流与更新

- `[initvar]` 条目禁用，供框架读取；公共初值只保存一份。不同开场确有差异时，再使用全量 `<initvar>` 或完整 `<UpdateVariable><JSONPatch>…</JSONPatch></UpdateVariable>` 补丁；全量块会替代对应角色初值基准。
- 普通卡默认使用无路由前缀的变量回流条目，保证模型看见当前状态。只有明确配置分离的剧情/变量模型时，才分别提供剧情摘要与更新端完整变量；逐端检查实际提示词，不因出现前缀就认定错误。
- “只输出合法更新块”仅约束更新部分，不禁止剧情正文。无变化时允许合法空数组 `[]`；强调条目仅在测试确有需要时启用。
- 不按模型家族硬编码 D0/D4；触发条件、顺序、插入位置与深度是不同设置。变量列表默认沿生成侧车 `after_char`；深度扩展须按装配器支持的 `extensions_json` 保存并检查导出结果。

## 正则与界面

- 显示专用：`markdownOnly=true, promptOnly=false`；提示词专用相反；双 true 同时处理两端但保留原始记录。双 false 会改写原文，不用于生成的美化规则。
- 剧情正文必须保留给模型。仅隐藏变量控制块与无语义占位符；结构化剧情需要保留或转为可读叙事，不整块删除。
- 未闭合更新块可在流式显示中临时收起，但提示词端不使用“从开标签删到末尾”的兜底。摘要缺失/为空/未闭合时保留原文，不能用摘要裁剪代替摘要生成。
- 酒馆助手面板：HTML 代码块交给对应前端渲染，按所在消息读取 MVU，等待框架初始化并订阅更新。原生 EJS `@@iframe`：模板阶段取值并转义输出，不假设浏览器脚本具有酒馆助手全局；实时面板使用前一种路径。
- 图鉴区分当前聊天解锁、跨档成就、界面偏好和资源缓存。只有明确要跨档共享的数据才用浏览器公共存储；其他数据按卡/聊天隔离。

## EJS 与条目路由

- EJS 支持 JavaScript、JSON 和数组操作；生成阶段与渲染阶段分开。项目不执行卡内模板、不自动联网或安装依赖，这是工作边界而非语言能力限制。
- 新控制器使用 `@@private` 隔离局部变量，不复用另一控制器的同名缓存。`await getwi` 目标优先使用稳定唯一名称或数字 UID，版本号写正文而非引用名称。
- 条目改名后运行诊断。静态检查覆盖本卡字面量引用及其可达禁用目标；外部世界书、动态拼接名称需要另行核对。阶段末提供兜底。

## 生成、检查与交付

- 文档中的 `node tools/…` 从项目根执行；桥接 cwd 在卡片 src 时使用 `node ../../../tools/…`，不通过更改源码边界规避限制。
- `mvu.mjs gen <定义.json> --card <卡名>` 默认仅补缺失的脚本/正则，保留已有同名项，包括停用设置。运行前先向用户展示变量树、生成范围、目标文件与可能覆盖项并取得明确确认。它不自动保存输出的世界书正文/侧车；相关正文与侧车必须按 `workflow/世界书写入指南.md` 先确认再写入 src。
- 调整现有 schema 或面板优先定向编辑。`--replace-generated` 是显式整体重建同名生成项，可能覆盖定制；先保留副本并核对差异。加手机 import 不需要重建面板。
- 按已确认的 `plan.modules` 选择下一个未完成模块，不因跳过状态栏/手机而跳过其他已选项。专用对话以绑定模块为本轮目标。
- 分层验收：结构 check → 静态 diagnose → 构建输出核对 → 独立测试聊天验证初始化、更新、编辑/重试/分支与回流。桥接只写 src、完成 check 后报告；打包由 studio/工具的明确动作执行。不把静态通过称为真机成功。
